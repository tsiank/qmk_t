# ciank_pad / Qmknrf5

已迁移到当前 QMK JSON 配置与公共 nRF5 功能。保留原 USB 身份
`3D92:8A42`、键盘名 `Ciank_pad`、21 键 / 5×5 电气矩阵与内部 LF RC 时钟。

## 硬件

- 行引脚：41、5、43、38、36；列引脚：29、45、9、10、13；ROW2COL。
- 唯一的第 0 行按键位于 `[0,4]`，其余四行各五键。
- 底灯：P0.03，20 颗 WS2812；未启用 RGB Matrix。
- 旋钮：A=P0.24、B=P0.22，分辨率 2，保留原方向翻转。
- OLED：SCL=P0.17、SDA=P0.15，SSD1306，地址 0x3C；0.91 英寸 128×32。
  若实际屏幕为 128×64，应在 config.h 改为对应显示尺寸后重新编译。
- 沿用旧 E73 配置：内部 LF RC，CTIV=16、TEMP_CTIV=2、ACCURACY=1。
- 未提供蜂鸣器引脚，因此未启用本地 Audio；支持 USB / BLE MIDI。

## 构建和刷入

```sh
make ciank_pad:default
make ciank_pad:oled
make ciank_pad:test
```

`default` 与 `oled` 共用 `keymaps/common/keymap.inc`，均显示 OLED；`test` 保留其原有测试键位。
硬件配置已移到键盘级 config.h，各 keymap 不再重复一份引脚配置。
旧 `lib` 和带“副本”的文件仅保留作参考，不参与构建。

生成的 BIN / HEX / UF2 位于 `.build`，打包应用 ZIP 后可在客户端“固件刷入”刷入。
没有要求重刷 Bootloader 或 SoftDevice。按住最上方静音键启动可触发 Bootmagic。
SYS 层提供 `QK_BOOT`（Nordic DFU）、`ENT_DFU`（保留原 Adafruit 0x57 入口）及重启，按实际 Bootloader 使用。

## 功能

- 基础层旋钮保留原音量方向；导航层翻页。
- 灯光层旋钮调整色相，按住 Ctrl 调饱和度、Alt 调亮度。
- SYS / BLE 层旋钮不发送按键。使用当前 QMK 同步 tap API，不再从 Nordic app_timer 回调释放按键。
- 灯光层补齐开关、灯效、色彩、速度、诊断、自测和 MIDI 打字伴奏控制。
- OLED 显示层、输出方式、电池电压 / 电量、底灯状态、Num/Caps 和 MIDI 伴奏状态；使用当前 bool 返回值接口。
- USB / BLE 共用 VIA 的五层键位与宏；原先 15 个自定义键码数值保持不变。
- 底灯音乐律动、键盘控制与 MIDI 伴奏复用 `platforms/nrf5/features`。

## 客户端

使用本次更新后的 Qmknrf5 客户端，在 VIA 页“加载键盘布局”选择发布目录
`Layouts/ciank_pad.json`，然后连接并读取。必须使用完整 5×5 电气矩阵，不能按 21 个按键推导成其他矩阵。

pad 使用能力状态 v2，报告底灯和 MIDI 可用，不报告矩阵灯、本地声音和按键音。
客户端自动禁用不支持的开关及本地演奏选项，开始律动仅开启底灯。
当前旋钮为上述固定分层功能，VIA 图编辑的是实体按键；尚未提供独立旋钮改键界面。

已做构建、原生回归和模拟客户端验证；OLED 的实际尺寸、接线及旋钮手感仍需刷入实机检查。


## R2 修正

R1 已包含 OLED 代码，但初始化时机早于 nRF SDK RTC / 电源管理准备完成。
R2 改为 SDK 启动后初始化，失败时每秒重试；当时仍沿用旧配置的 SCL15 / SDA17，R4 已按原理图修正。
恢复矩阵读取前的 `GPIO_INPUT_PIN_DELAY=2` 微秒等待。
USB 媒体键改用持久 FIFO，直到异步发送完成才复用缓冲区，BUSY 时重试并保留松开报告。
LIGHT_STATUS 诊断增加 `oled=0/1`，结合 `twi` 计数检查显示初始化 / 通讯问题。
刷入 `ciank_pad-qmknrf5-r2.zip` 即可测试，无需为这些软件问题先替换 Bootloader。

## R3 USB / 自动休眠修正

USB VBUS 存在或 USBD 外设启用时，禁止蓝牙广播超时和空闲计时进入 System OFF。
启动时直接检查 VBUS，避免 USB 电源事件尚在队列中就误启动蓝牙广播。
自动休眠回调只设置请求，主循环等待 EEPROM 写入结束后执行；休眠关闭底灯不写入 OFF 状态。
唤醒引脚配置按 ROW2COL / COL2ROW 区分，匹配 pad 的 ROW2COL。
OLED 首次初始化推迟到主循环处理 USB 事件后至少 250 ms，失败时每秒重试。

GCC 15 / newlib 的 `_close`、`_read`、`_write`、`_lseek`、`_fstat`、`_isatty`、`_kill`、
`_getpid` 警告来自 `libnosys` 的无操作系统接口。固件未提供标准文件 / 进程服务；USB、BLE、OLED 不使用这些接口。
保留 `nosys` 链接和构建后的半主机陷阱检查，不通过屏蔽链接警告掩盖接口状态。

## R4 原理图核对与键位存储

根据 `Schematic_JasonFly_pad_2020-08-13_13-01-37.pdf` 的 U2 / U1：

| 信号 | nRF GPIO | 配置数值 |
| --- | --- | --- |
| R0 / R1 / R2 / R3 / R4 | P1.09 / P0.05 / P1.11 / P1.06 / P1.04 | 41 / 5 / 43 / 38 / 36 |
| C0 / C1 / C2 / C3 / C4 | P0.29 / P1.13 / P0.09 / P0.10 / P0.13 | 29 / 45 / 9 / 10 / 13 |
| OLED SCL / SDA | P0.17 / P0.15 | 17 / 15 |
| 旋钮 A / B | P0.24 / P0.22 | 24 / 22 |
| WS2812 LED | P0.03 | 3 |

矩阵和旋钮引脚与旧配置一致；OLED 两线反接于配置，灯光数据脚也有误，R4 已更正。
原理图 OLED 由 VCC 供电，USB 可经 D46 / U4 提供 VCC，无需电池才能显示。

VIA 存储增加一个 keymap 标记，防止同日刷入 default / test 继续使用上一个固件的键位。
R4 第一次启动，以及 default / oled 与 test 互相切换时，重新载入固件键位并清空 VIA 宏。
同一 keymap 重启 / 重刷仍按 QMK 原有日期有效性规则保留改键。

`default` / `oled` 保留仓库旧 default 基础层（每行从左到右）：

```text
                                       静音
音量+  音量-  音量+  蓝牙广播  9
4      5      TO(NAV) TO(NAV) TO(RGB)
1      2      3       小键盘*  TO(SYS)
0      宏0    .       小键盘/  =
```

`TO` 是持续切层，NAV / RGB / SYS 的左上方主按键可返回 BASE。
`test` 基础层无切层键：

```text
                                 静音
7       8      9      0        退格
4       5      6      7        回车
1       2      3      空格     空格
蓝牙广播 宏0    .      小键盘/  =
```

旋钮在 BASE 为音量，NAV 为 Page Up / Page Down，RGB 为色彩调整；SYS / BLE 不发送旋钮按键。
Home / End 不在当前旋钮回调中，若 R4 test 仍出现此行为，应结合实际按键顺序及 VIA 读回键位继续排查。

## R5 公共显示与旋钮模块

显示与旋钮实现已移到 `platforms/nrf5/features/oled_status.c` / `encoder.c`，
由 `NRF5_OLED_STATUS_ENABLE` / `NRF5_ENCODER_ENABLE` 分别启用。
本目录只保留一行回调转发、硬件引脚、屏幕标题/层名及旋钮动作表，保持 R4 的实际行为。
完整接入示例见 `platforms/nrf5/features/README.md`。

I2C 支持 OLED / 矩阵灯重复初始化；有 OLED 时关灯保留总线。
屏幕可通过 QMK 位图 API 显示图标和预制中文字模，当前默认页面仍为英文。

无需修改公共模块里的键盘名称或加入完整中文字库。

名称占上半部左侧 64×16；右侧两行显示层名和 USB / BLE；
下半部保留 RGB 与 Num / Caps / MIDI 状态，不显示电池行。

## R7 传统时刻

启用公共 `NRF5_CLOCK_ENABLE`。保留“紫雪蓝海”；右上显示 HH:MM、层名和连接，
下半部改为传统时刻。每时辰两个小时，奇数小时为初、偶数小时为正；
每小时 00/15/30/45 分分别开始初刻/一刻/二刻/三刻。
11:45=午初三刻，12:00=午正初刻，23:00=子初初刻，00:00=子正初刻。

请配套本次更新的 Qmknrf5 客户端。设备连接后自动同步 Windows 本地时间，
控制连接保持时每分钟校正。未校时显示“待校时”；键盘不断电/不进 System OFF 时，
关闭客户端仍会继续走时。断电需重新校时，不要求电池才能通过 USB 显示。
屏幕的原有 60 秒空闲熄屏仍保留，按键/旋钮可唤醒，计时不受熄屏影响。

## R8 排版与屏幕电源

上方左侧保留“紫雪蓝海”，右侧两行显示连接/电量和层号/层名。
下方传统时间从左侧开始，其后直接显示 12×16 数字时间，例如“午初三刻 11:45”。
本次测试板未装电池，`NRF5_OLED_BATTERY_AVAILABLE=0`，显示 `--%`。
接电池时还需按原理图配置/校准 AIN2/BAT_TOG 测量电路后启用百分比；
旧共享 ADC 默认 AIN3 是 pad 的矩阵行，不能用于本板电量。

新版客户端“设备连接 → 键盘控制 → 屏幕”提供：
- 自动：默认模式，USB 供电常亮，蓝牙独立供电空闲 60 秒熄屏，按键/旋钮唤醒。
- 常亮：保持屏幕亮起，不受显示空闲超时影响。
- 熄屏：保持屏幕关闭，按键/旋钮/刷新均不唤醒；需通过客户端切回自动/常亮。

选择保存在 RAM，键盘复位后恢复自动。屏幕关闭不停止计时，也不等于键盘深睡。
R8 固件需搭配 R8 客户端使用屏幕设置；新客户端仍可连接旧固件，届时屏幕选项禁用。
