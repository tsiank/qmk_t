# ciank67 音乐律动 · WinUI 3

C# / WinUI 3 Windows 客户端，使用原生 Fluent 控件、系统主题与 Mica 背景。沿用 R6 固件的 20 字节频谱协议；不需要升级 nRF5 SDK，不需要 Python。

## 使用

1. 此发布包不包含系统运行时。首次使用需安装 **.NET 10 Runtime（x64）** 和 **Windows App Runtime 2.7（x64，或兼容的更高 2.x 版本）**。已安装则无需重复安装。面向 Windows x64，最低 Windows 10 2004；Windows 11 可显示 Mica 效果。
   - [.NET 10 Runtime 官方下载](https://dotnet.microsoft.com/zh-cn/download/dotnet/10.0/runtime)
   - [Windows App Runtime 官方下载](https://learn.microsoft.com/windows/apps/windows-app-sdk/downloads)（选择与 2.7 SDK 匹配的 x64 安装程序）
2. 保留发布包的完整目录，双击 `Ciank67Music.exe`。安装运行时后可供多份程序共用，分发 ZIP 不附带安装程序。
3. 首次可以选择 **仅预览**，打开 **演示模式**，点击 **开始律动**，在不连接键盘时检查界面和频谱。
4. 键盘建议刷入 `ciank67-music-r15-color-picker.zip`。R15 支持客户端选择两种矩阵律动效果，USB 名称为 `ciank67`，仍沿用 R6 音乐协议。刷入后重新拔插 USB。
5. USB：选择 **USB** → **刷新设备** → 选择键盘。蓝牙：先在 Windows 设置配对键盘并拔掉 USB，再选择 **蓝牙（已配对）** 并刷新。蓝牙列表包含其他已配对设备，请选择键盘；已连接的键盘不需要重新广播。
6. 选择声音的 **播放设备**。程序采集该设备正在播放的声音，不采集麦克风，也不保存录音。
7. 关闭演示模式，选择矩阵灯 / 底灯和 **矩阵律动效果**、**律动配色**，点击 **开始律动**。灵敏度、帧率、效果和两组灯的选择可在运行中调节。
8. **停止**或关闭窗口会发送恢复指令。连接中断时，固件也会在约 750 ms 无数据后恢复原灯效。

键盘上的 `RM_TOGG` / `UG_TOGG` / `RGBG_TOG` 仍可关灯，客户端不会强制打开手动关闭的灯。Caps Lock 保留原有覆盖优先级。更换系统默认播放设备后，请停止、刷新并重新开始。

蓝牙若报找不到音乐服务，先确认刷入 R6、键盘当前使用蓝牙，再尝试在 Windows 设置移除并重新配对以清理旧服务缓存。演示模式正常而实际音乐没有频谱时，检查所选播放设备、音量和灵敏度；部分独占播放或受保护音频可能无法回环采集。

## 从源码构建

Windows 安装 .NET 10 SDK，双击 `build.cmd`。也可在当前目录执行：

```powershell
dotnet run --project Ciank67.Music.Tests -c Release
dotnet publish Ciank67.Music.App -c Release -r win-x64 --self-contained false -o publish\win-x64
```

输出为 `publish\win-x64\Ciank67Music.exe` 及其依赖。发布采用依赖系统运行时的轻量方式，不包含 .NET 或 Windows App SDK 运行时；分发时保留整个目录。请发布到空目录，避免混入旧版自包含发布的 DLL。源码提供 `Ciank67Music.sln`，可用支持 .NET 10 的 Visual Studio 打开。构建需要联网恢复 NuGet 包。

- `Ciank67.Music.App`：WinUI 3 界面、WASAPI 回环采集、USB HID、Windows BLE GATT。
- `Ciank67.Music.Core`：协议、PCM 解码、2048 点 FFT、16 段频谱、音频环形缓冲、发送/停止流程。
- `Ciank67.Music.Tests`：不依赖硬件的核心回归测试，可在 Linux 或 Windows 运行。

界面使用 C# 创建原生 WinUI 控件，App.xaml / MainWindow.xaml 负责标准资源和窗口初始化；没有 WinForms、WebView 或 Python 运行时。采集和数据发送不在 UI 线程执行；绘图只读取最新频谱，不排队补发旧帧。USB 和 BLE 与原 Python 客户端共用固件协议，请不要同时运行多个控制程序。

NuGet：引用 Microsoft.WindowsAppSDK.WinUI / Runtime 2.7.0 及其必需依赖、NAudio.Wasapi 2.2.1、HidSharp 2.6.4。不引用 Windows App SDK 总包，避免带入 AI、ML、搜索、Widgets 等未使用组件。第三方组件许可证随发布包附带。

.NET / WinUI 运行时由系统安装，本 ZIP 不再捆绑。目录中的 `Microsoft.Windows.SDK.NET.dll`、`Microsoft.WinUI.dll`、`WinRT.Runtime.dll` 等属于应用运行必需的托管 API 投影和互操作依赖；`Microsoft.WindowsAppRuntime.Bootstrap*` 用于查找并加载已安装的共享运行时，应保留。WinUI 所需的 WebView2 托管类型投影保留，但本程序未使用浏览器控件，其原生组件和 Loader 不发布。不要凭文件名手动删除必需依赖。

## USB 名称与兼容性

客户端按 VID/PID 和音乐接口 Usage 筛选，不按产品名筛选。新版固件使用 `FEED:C475`，客户端也兼容旧版的 `1915:520B`；即使名称还是 `nRF52 USB Product`，只要音乐接口已经枚举就能识别。

如果提示“已找到键盘的 USB 设备，但未检测到音乐接口”，说明普通键盘接口可见，音乐接口还未出现。确认 USB 连的是已刷音乐固件的同一块键盘，刷入 R15 后重新拔插并刷新设备。USB 产品名在仓库 `keyboards/ciank67/keyboard.json` 的 `keyboard_name` 字段中修改。

应用图标为原创的键盘与彩色频谱图案，包含 16～256 像素多尺寸图层，同时用于 EXE、窗口和任务栏。图标及可重生成的绘制脚本位于 `Ciank67.Music.App/Assets/`；仅重新绘制图标时需要 Pillow，构建及运行客户端无需 Python。

## 矩阵律动效果

- **频谱柱**：R13 在键盘上将 16 个输入频段合为 7 组宽柱，每组两列按键，按键盘矩阵对齐。从左到右表示低频至高频，自下向上显示强度；使用纵向绿→黄→红配色、即时上升与短尾回落，不再显示独立白色峰值。客户端右侧仍显示原始 16 段输入频谱。
- **双心共舞**：键盘沿中线分成左右两区，两组同心彩色环带随音乐整体强度平滑扩张、收拢，颜色连续流动，边缘柔和渐隐。两个区域使用相同的系统混合音频，效果不表示左右音频声道。矩阵灯的速度按键控制流彩速度。

选择会随下一帧通过 USB / 蓝牙下发，播放中无需停止或重新连接。底灯仍显示原有频段强度，客户端预览保持显示输入音频的 16 段频谱。停止或断流后恢复原灯效，不改写键盘保存的模式。双心共舞需要 **R10 或更新固件**；R6～R8 固件只能使用默认频谱柱。旧客户端可继续使用 R10 的频谱柱；R9 客户端的“双中心放射”选项也可直接选择新效果，但界面仍显示旧名称。

“双心共舞”的形态参考 [HFD SDK 的同名模式](https://docs.driveall.cn/kit/music-v2.html)，按 ciank67 的实际灯位重新绘制；R10 修正 R9 逐方向短脉冲造成的闪烁感。客户端右侧仍显示输入频谱，不代表键盘灯效图案。

R12 加快两种音乐模式响应：客户端两种模式均使用快速攻击和短回落，频谱固件不再叠加上升低通，只保留 40～120 ms 的全高回落上限（默认约 80 ms）。请配套更新客户端和固件。双心共舞的固件包络也从 100/360 ms 缩短到 10/45 ms，保留连续环带和渐隐边缘。

R13 进一步修正幅度映射：弱、中等输入使用较低的柱高和双心半径，同时整个柱体及双心中心的亮度也跟随音乐；取消双心最小半径及提前满亮。客户端和底灯数据不变，使用现有 R12 客户端即可，只需刷入 R13 固件。

## 律动配色

客户端可选择 **彩光** / **纯光**，默认彩光，可在播放中实时切换，适用于频谱柱、双心共舞及底灯。R15 纯光使用下方调色器选择的颜色，两组灯保留各自亮度；旧客户端不发送自选颜色时仍使用键盘保存的灯色。律动幅度、亮度变化、响应速度保持 R13 的行为；停止后恢复原灯效。此选项只在当前音乐流中生效，不额外写入 EEPROM。

自选纯光颜色需要配套 **R15 固件**。旧客户端仍可控制新版固件的彩光；新客户端默认彩光也兼容旧版音乐固件。客户端右侧保持显示输入频谱。

## 选择纯光颜色

R15：将“律动配色”切换到 **纯光**，点击色块 / 十六进制值旁的 **选择颜色**，使用色盘、RGB 或十六进制输入调色。默认白色，播放中修改会实时发送；彩光模式下颜色按钮不可用。矩阵灯、底灯使用同一所选颜色，保留各自的亮度和开关、音乐响应及 Caps Lock 优先级。

需要配套 **R15 固件与客户端**；颜色只在当前音乐流中生效，不覆盖键盘保存的普通灯色。关闭或停止律动后恢复原灯效。黑色会使纯光音乐帧变黑。

纯光模式下，右侧 16 段输入频谱预览会使用所选颜色；它的柱高仍表示输入音频，不是键盘灯位图。切回彩光后预览恢复多色。

## USB 写入超时修复

如果点击开始时出现 `Operation timed out 500`，这是 USB 中断输出写入超时。新版客户端首次遇到此超时会将同一个报告通过 `SET_REPORT(Output)` 控制传输重发；之后本次连接的音乐、颜色和停止包都沿控制通道发送，避免每帧重复等待超时。原中断路径正常时继续使用原路径。

此修复只需更新客户端，R15 固件已支持控制传输接收，不必重刷。两条通道都失败时，界面会说明操作阶段，并在程序目录写入 `usb-error.log`；可据此进一步检查具体电脑的 USB 连接。两种写入均串行等待完成或取消，控制通道也有超时并在释放缓冲区前结束未完成的 I/O。音乐集合输出报告必须为 21 字节，长度异常会提示重新插拔并刷新设备。蓝牙和音乐协议不变。


## MIDI 演奏（集成电脑合成器）

客户端新增独立的“MIDI 演奏”面板，无须另开 MIDIberry。该功能需要 R16 或更新固件；边打字边演奏需要 R17 或更新固件。音乐律动和 MIDI 可分别启停，也可同时运行。

1. USB 连接键盘；蓝牙则先在 Windows 设置中配对。升级新增 MIDI 服务的固件后，如果没有蓝牙 MIDI 端口，删除旧配对后重新配对。
2. 关闭 MIDIberry、MIDI 检测工具或其他占用该输入的程序，点击“刷新 MIDI 设备”。
3. “键盘 MIDI 输入”选择 ciank67，默认输出为“内置合成器 · 默认电脑扬声器”；也可选择 Windows 列出的其他合成器输出。
4. 点击“开始演奏”。键盘灯光层 P 开启打字伴奏，或 U 开启纯演奏。按键后会显示转发计数和音符/力度/通道，电脑扬声器播放声音。
5. 音色可实时选择钢琴、电钢琴、音乐盒、马林巴、吉他、小提琴、弦乐或长笛。内置合成器采用系统默认音频输出；外部输出是否支持这些 GM 音色由设备决定。
6. “全部停音”释放全部通道的延音与音符，保持输入连接；“停止演奏”和关闭窗口会停音、释放 MIDI 端口。键盘上的 MIDI 模式开关仍由 P/U/I 控制，客户端停止不会改变该开关。

刷入固件、切换 USB/蓝牙或重新连接后，停止演奏、刷新设备、重新开始即可，不必重启整个客户端。检测到输入设备移除会停止；未检测到断开时可手动停止/刷新。端口不会在重新连接时自动开始演奏。

仅自动选择名字包含 ciank67 的输入，其他键盘需手动选择。电脑合成器输出列表隐藏名字包含 ciank67 的端口，避免误选键盘蜂鸣器。MIDI 输入和灯光 HID/GATT 接口独立，刷新 MIDI 不会停止正在运行的律动。

声音已经播放但灯光不跟随时，确认律动的播放设备与系统默认音频输出相同，并关闭演示模式。合成器声音也能像其他系统声音一样驱动 FFT 律动。

发布继续使用共享 .NET 10 / Windows App Runtime，不捆绑运行时，不新增 MIDI 驱动或第三方合成器包。Windows 专用 MIDI 测试：`dotnet run --project Ciank67.Midi.Tests -c Release`。


## R19：客户端控制键盘开关

先刷入配套 `ciank67-usb-concurrent-r20.zip`。客户端左侧选择 USB / 蓝牙及目标键盘，在“键盘开关”卡片点击“连接键盘控制”，客户端先读取键盘实际状态，再开放操作：

- 按键矩阵灯、底灯总开关（区别于原有“按键矩阵灯 / 底灯”的律动参与选择）。
- 键盘本地声音、键盘按键音开关；本地声音不影响电脑合成器音量。
- 演奏模式：关闭演奏/正常打字、本地蜂鸣器音乐模式、MIDI 纯演奏、MIDI 打字伴奏。模式互斥，切换会释放原有音符。

无需开启灯光律动即可控制，控制连接、律动、电脑 MIDI 演奏均可分别启停。要听电脑 MIDI 声音，还需在“MIDI 演奏”卡片点击“开始演奏”；然后可在这里将键盘设为“MIDI 打字伴奏”或“MIDI 纯演奏”，无需再按键盘 U/P。

客户端每秒查询一次实际状态，键盘物理按键修改后也会同步显示；每次只写用户操作的那个字段，查询不写 EEPROM、不开始律动，也不延长音乐帧超时。灯光和音频总开关沿用原有保存行为；演奏模式仍仅保存在 RAM。客户端断开或退出时保留键盘开关状态，电脑合成器则正常停音并释放端口。底灯关闭后，Caps Lock 指示仍按原有规则显示。

旧固件不能回读时，会显示需要 R19 的提示，并禁用开关；原有律动/MIDI 面板仍可使用。BLE 新增只读状态特征 `c1a00003-7d9b-4c7d-a568-7294e2166700`，首次升级如读取不到，请在 Windows 删除旧配对后重新配对。

控制沿用 20 字节传输，USB HID Report ID 4，BLE 使用原写入特征。请求：`C7 03 sequence mask values mode 00…`（绝对设置）或 `C7 04 sequence 00…`（查询）；mask 位0/1/2/3/4分别为矩阵灯/底灯/audio/clicky/演奏模式，values 位0～3为开关，mode 为0～3。回复：`C7 83 sequence flags mode 01 00…`。命令只在主循环执行，响应在执行后生成。USB 使用原音乐 IN 端点，BLE 独立状态特征避免频谱写入覆盖回复。


## R20：USB 律动与开关并发修复

请配套更新 `ciank67-usb-concurrent-r20.zip` 和共享连接版客户端。客户端按 USB 设备路径共享一个 HID 连接、写入锁和回退状态，控制命令与状态回复作为完整事务串行；停止控制或律动只释放各自的引用，最后一个使用者停止后才关闭物理连接。

固件修复 SDK 15 排队事件中的重复 OUT/WAITING 接收：OUT/OK 已为下个包重新启动 DMA 时，后续排队的 WAITING 事件保留现有接收，不再返回 BUSY 导致 SDK 挂起端点。原生回归测试在旧函数上失败，修复后通过。

旧版端点一旦已挂起，关闭客户端、重新拔插 USB 再测试。R20 协议与 R19 相同，BLE 数据格式及独立灯光/音频开关不变。


## 熄屏期间继续律动

新版客户端在律动会话启动后申请 Windows SystemRequired / ExecutionRequired 电源请求，使采集和发送在允许的系统电源策略下继续运行；不申请 DisplayRequired，屏幕仍可正常熄灭。停止律动、异常退出会话或关闭程序时清除请求，不修改系统电源计划，也不要求刷新键盘固件。此请求按句柄管理，不依赖异步任务当前运行在哪个线程。

用户主动让电脑睡眠、合盖触发睡眠等操作仍受系统策略管理。显示器经 HDMI/DisplayPort 同时充当音频输出时，关闭显示器电源可能移除音频设备，这与桌面进程被暂停不同；此时需选用仍在线的播放设备。
